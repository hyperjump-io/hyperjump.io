# API reference

A repo with `api` in `sources.js` (json-schema and browser) gets API pages at
`/<section>/api/`, in the section's sidebar as "API". They're generated by
TypeDoc, through `starlight-typedoc` and `typedoc-plugin-markdown`, so they're
Starlight pages, with the site's look, search, and link checking. They
replaced each repo's TypeDoc HTML on GitHub Pages.

- The entry points are the declaration files the repo's `package.json`
  exports. The repo's `typedoc.json` is used if it has one. That's where a
  repo keeps its own options, like `sourceLinkTemplate` and the
  `externalSymbolLinkMappings` to another package's API.
- `plugins/typedoc-import-paths.js` names each module by its import path
  (`@hyperjump/json-schema/v1`), from the `exports`, instead of TypeDoc's
  file path (`dialects/v1`). Its router leaves the package's name out of the
  URL, since the section is the package (`/json-schema/api/v1/`).
- The package's main module is the API's front page.
- Links from one package's API to another's are written as
  `https://hyperjump.io/<section>/api/...` in the repo's `typedoc.json`. The
  site makes them site paths, so they're checked.

TypeDoc needs the whole repo and its dependencies, not only `website/`, so
these repos are cloned in full and get `npm install`. A dependency linked
with `file:`, like `../uri`, is in `sources.js` without a section, so it's
cloned next to them.

Rejected: serving TypeDoc's own HTML under the site. It's a different look,
outside the site's search and sidebar, and its links aren't checked.

## Known limitations

- The link check doesn't check a heading anchor in a link from a generated
  page (`/browser/api/classes/hyperjump/#nope`). It does check the page.
